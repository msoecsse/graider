# PR12-5: roster-manager visual rebuild

## Summary

Rebuilt `RosterManagerPage` as the verified §5.6 roster workspace using the
PageHeader, bulk section summaries, first-class provenance, shared roster
parser/diff, dirty-state bar, structured review, typed destructive
confirmations, and Technical details supplied by PR12-1 through PR12-4.

The supported student model remains deliberately honest: the table is
`Student ID · GitHub · Status`. No unsupported Name field or SIS lookup was
invented.

## Route Term Context

`RosterManagerRoute` passes the resolved course-term card's canonical term
slug, course title, and term title into the page. The page no longer owns a
second selectable term state and no longer asks faculty to select the routed
term again. The breadcrumb remains `Dashboard > CSC1120 · Spring 2027 >
Roster`, and the header meta uses the same resolved context.

## Page Structure

The rebuilt page is:

1. `PageHeader` with the `roster-manager-title` landmark relationship and a
   roster overflow menu.
2. Visible section tabs and adjacent **Add section** action.
3. A quiet source/provenance bar with **Replace from CSV**.
4. A two-column students workspace and section faculty/stats sidebar that
   stacks at narrower widths.
5. `TechnicalDetails` for roster/source/course paths.
6. `UnsavedChangesBar`, rendered only for a real draft change.

## Section Tabs and Bulk Summaries

The page makes one `getRosterSectionSummaries` request for the canonical routed
term. Ready sections show persisted student counts; missing sections show **No
roster**; invalid sections show **Needs attention** and remain selectable.
Draft row edits update only the selected-section stats, not persisted tab
counts.

An explicit generation guard prevents stale section loads and stale summary
refreshes from replacing newer state. Summaries refresh after successful save,
roster removal, section removal, and new-section creation.

## Source Bar

Saved provenance displays **CSV upload** or **Manual edit** with
`formatReadableDateTime`, omits an author when `updatedBy` is null, and uses
**Update time unavailable** rather than raw invalid timestamp text. Legacy
rosters show **Not recorded** and explain that the next roster-data save will
establish provenance. Malformed provenance diagnostics remain in the page's
attention surface without making usable rows unavailable.

The bar also contains the noninteractive **Canvas sync not connected** chip and
the accessible CSV file control. Canvas integration was not added.

Persisted provenance remains visible while pending intent is separately labeled
**Source after save: CSV upload/Manual edit**. A successful local save adopts
the canonical returned source; a failed save retains pending intent.

## Shared Parser/Diff Integration

The renderer directly imports dependency-free
`parseAndValidateRosterCsv`/`diffRosterRows` from `src/roster/roster-shared`.
The old `parseUploadedRoster`, manual header constants, and naive comma split
were deleted. Renderer uploads now inherit quoted values, escaped quotes, CRLF,
BOM stripping, reordered canonical columns, tolerated legacy/extra columns,
normalization, warnings, and validation from PR12-2.

This is the smallest established build-boundary change: production Vite can
bundle the pure TypeScript dependency directly, while development server
filesystem access is allowlisted only for the UI root and the shared module's
`src/roster`, `src/io`, and `src/diagnostics` directories. No filesystem API,
generic backend-function bridge, or copied parser was exposed.

Backlog item 36 remains open. Three parser paths still need convergence:
`src/roster/roster-loader.ts` + `src/io/csv.ts`,
`ui/electron/courseSetupService.ts`, and
`ui/electron/rosterManagerService.ts`.

## Student Table and Status Actions

Student ID and GitHub remain editable. Section is synchronized internally and
is no longer a redundant visible column. Blank GitHub values receive attention
styling and a **Not set** placeholder.

Each row renders a humanized status chip: **Active**, **On hold**, or
**Dropped**. Dropped uses the error treatment. The accessible row overflow
menu changes status using **Mark active**, **Put on hold**, and **Mark dropped**
while preserving canonical machine values, and also provides **Remove student
row**.

Editable rows use UI-only monotonic draft keys, never array indexes or editable
student IDs. The keys are stripped naturally because IPC requests are built
from each draft's `RosterRow` only.

## Faculty and Stats

The sidebar renders assigned faculty as removable tokens plus an add form.
Faculty membership, normalized case-insensitively, is the meaningful dirty
state; ordering alone does not create a change. Faculty-only changes preserve
existing roster provenance.

The stats card shows current-draft Students, Active, On hold, and Dropped
counts. It is omitted when roster rows are not trustworthy.

## Dirty State and Discard

Successful loads capture immutable `baselineRows`, `baselineFaculty`, and
`loadedSource`. Current state is `rows`, `faculty`, and `pendingSourceKind`.
`diffRosterRows` is the sole student diff; a narrow membership diff handles
faculty.

Added rows are success-tinted, changed rows warning-tinted, and removed rows
remain visible as error-tinted tombstones with prior data and **Undo removal**.
Text badges accompany every color treatment.

Discard restores rows/faculty and clears pending source intent for an existing
section. Discarding a new section cancels the draft without backend mutation
and returns to the prior section. Switching tabs or starting another section
while dirty opens the shared confirmation dialog; cancel stays on the current
draft and confirm performs the requested navigation.

## Review and Save

**Review and save** first calls the existing authoritative
`previewRosterSave`. Invalid previews remain on the page with diagnostics.
Valid previews open `ConfirmationWithPreviewModal` with student counts,
row-level Added/Removed/Changed entries, humanized changed-field detail,
faculty additions/removals, and explicit new-section creation copy.

The review repeats the safety fact that removing a roster row or marking it
dropped does not delete the student's repository or published reports. Saving
requires the modal's explicit confirmation.

## Destructive Actions

The PageHeader overflow contains **Clear roster rows**, **Remove roster**, and
**Remove section**. All three require typing the selected section ID.

Clear is a staged empty draft and never calls `saveRoster` directly. The two
backend removals preserve existing mutation/publication behavior and use copy
that does not expose filesystem paths or claim student repositories are
deleted.

Code inspection confirmed an adjacent contract defect: `removeRoster` and
`removeSection` both remove the configured section from `term.yml` and delete
roster/source files. PR12-5 preserves and accurately describes that behavior;
backlog item 44 records the naming/semantic mismatch for a separate decision.

## Technical Details

Roster path, source metadata path, and course folder path appear only in the
copyable `TechnicalDetails` disclosure. Header metadata, normal status copy,
toasts, and destructive confirmation prose contain no raw path.

## Publication Feedback

A successful local save closes review, raises **Roster saved.**, updates row
and faculty baselines, adopts the canonical returned source, clears dirty
state, retains the selected section, and refreshes summaries without reload.

Publication failure after local success performs the same local-state updates
and presents **Saved locally** recovery guidance. Local failure throws into the
shared modal error surface and preserves draft state/source intent for retry.

## Accessibility and Responsive Behavior

The main landmark resolves through `PageHeader`'s heading ID. Tabs expose
selected state and complete accessible names; every editable input and row menu
has a student-specific label; file upload remains keyboard accessible; chips
and diff tints include text; typed confirmation and review use shared focus-
managed dialogs; toast/diagnostics retain live-region semantics.

Tabs scroll in a controlled container at narrow widths, the sidebar stacks,
and the student table scrolls within its panel rather than widening the page.

## Assumptions Made

- A configured term's first section is the initial selected tab.
- Faculty ordering has no semantic meaning; normalized membership does.
- A missing roster saved for the first time uses manual provenance unless CSV
  replacement is the last roster-data action.
- Existing `removeRoster` semantics are preserved despite the product-name
  mismatch.
