# PR12-4: first-class roster source/provenance

## Summary

Added persistent, trusted roster provenance without changing the roster-manager
layout. PR12-5 can load and immediately render the canonical source returned by
the existing roster load/save IPC calls.

## Data Model

`RosterSourceKind` is exactly `"csv_upload" | "manual_edit"`.
`RosterSource` contains `kind`, canonical ISO `updatedAt`, and nullable
`updatedBy`. `RosterSaveRequest` accepts only optional `sourceKind` intent;
`RosterLoadResult` and successful `RosterSaveResult` expose optional canonical
`source`.

## Persistence Format

Each source is stored beside its roster at
`terms/<termCode>/rosters/section-<sectionId>.source.json`:

```json
{
  "schemaVersion": 1,
  "source": {
    "kind": "csv_upload",
    "updatedAt": "2026-09-22T22:00:00.000Z",
    "updatedBy": "jones"
  }
}
```

The JSON is deterministic, indented with two spaces, and ends with a newline.
The roster CSV remains unchanged.

## Trust Boundary

Runtime validation accepts only the two source-kind strings and rejects
renderer-supplied `source`, `updatedAt`, or `updatedBy`. No new IPC channel was
added. The main-process save handler creates trusted save dependencies and the
persistence service constructs the canonical source only after confirmation and
successful preview validation.

## Source-Kind Semantics

Replace from CSV sets pending `csv_upload`. Editing a student ID, GitHub
username, or status; adding/removing a row; or clearing rows sets
`manual_edit`. The most recent roster-data action wins. New/missing blank
rosters start as `manual_edit`. Faculty-only edits do not set an intent and
therefore preserve existing provenance.

## Faculty Identity and Timestamp

The main process loads `currentFacultyMsoeUsername` through the existing local
settings service. Missing identity persists as `null`. The timestamp comes from
an injected `now` dependency at confirmed save time and is persisted with
`toISOString()`; tests use a deterministic clock.

## Load/Save Contract

`getRosterForSection` returns valid source metadata when present and no source
for legacy/missing metadata. `saveRoster` returns the exact source persisted.
The student-access-page and course-publication wrappers retain that field via
their existing generic result spreading.

## Publication

The managed course path allowlist now admits only
`terms/<term>/rosters/section-<safe-section>.source.json`. Neighboring JSON,
noncanonical `.source.json`, nested paths, and source files outside `rosters/`
remain unrelated. Tracked sidecar deletion is publishable. Existing explicit
staging, unrelated-file, and push protections are unchanged.

## Removal Behavior

Roster and section removal derive and delete the canonical source companion.
Missing legacy companions are harmless. The existing term rollback now also
restores snapshots of roster/source files if a deletion fails.

## Renderer Classification

The page keeps loaded canonical source state separate from pending source-kind
intent. Successful local saves adopt returned source and clear pending intent,
including when later Git publication warns. Failed local saves retain intent
for retry. No source bar or PR12-5 visual work was added.

## Backward Compatibility

A missing sidecar is normal and does not trigger migration or writes. A
malformed, structurally unexpected, invalid-kind, invalid-time, or unsupported
version sidecar is ignored with a diagnostic while valid roster rows remain
ready. Reads never fabricate source from CSV existence, file metadata, or Git.

## Local Write Consistency

Roster CSV and source JSON are first written to adjacent temporary files. The
CSV is atomically renamed first and the source second. If the source rename
fails, the prior CSV and term content are restored; temporary files are cleaned
up best-effort and the save reports failure. A source is never placed at its
canonical path before the roster write completes.

## Assumptions Made

The existing local-settings loader remains authoritative for faculty username
normalization. A new or currently missing roster saved with zero rows is a
manual roster unless the faculty used Replace from CSV.
