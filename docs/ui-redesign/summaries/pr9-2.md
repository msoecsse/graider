# PR9-2: grade preview, one page whose state changes

## Summary

Applied PR9-1's pattern (`57d7e21`) to `GradePreviewPage.tsx`: merged the two
panel sets (preview and dispatch result) into one state-driven page, per
README section 5.4.

- **One plan table**, not a preview table and a separate result table. A new
  merge module (`gradePreviewMerge.ts`) joins each preview row with its
  dispatch result by student identity into one `GradeRowState`. The table's
  Status/Reason/Workflow cells read from the result once it exists, the
  preview before that -- the same table updates in place.
- **One summary sentence**, not two four-box counter panels. Tallied
  directly from the same merged rows the table renders, so the sentence's
  counts agree with the rows shown by construction.
- **One diagnostics region**, shown only when non-empty.
- **Same design as PR9-1**: a shared row type with an optional result
  status, not two types behind a shared presentation layer.
- **Confirmed simpler than apply preview, as anticipated**: there is no
  group mode on this page at all, so there is one merge function, not two,
  and no `mergeGradeGroupRows` counterpart.

No backend or IPC change was needed.

## The two things PR9-1 found, checked here

**The group-mode empty array.** Does not apply. Traced
`src/grade-preview/grade-preview-builder.ts:568-594`: even when the
underlying repository is group-owned (`normalizedTargets?.repositoryMode
=== "group"`), the backend still builds one row per _student_ (mapping each
group target back to its member students via `target.studentIds`), not one
row per group. `plan.repositories` is never emptied the way apply preview's
group mode empties it. Confirmed there is no count-mismatch bug to fix here,
and didn't invent one.

**The separate result vocabulary.** Real, and different again from both
existing vocabularies. Traced `GradeDispatchResultRepositoryStatus` (already
declared in `gradePreviewTypes.ts`) to
`dispatched | skipped | failed | blocked` -- "dispatched" where apply
preview's individual result status uses "created"/"updated" (grading
dispatches a workflow run; it doesn't create or update a repository). This
vocabulary was **already fully and correctly handled** by an existing
function, `formatGradeDispatchResultStatus` -- just defined inline in
`GradePreviewPage.tsx` rather than in `gradePreviewReadiness.ts` the way its
apply-preview counterpart (`formatApplyResultRepositoryStatus`) lives in
`applyPreviewReadiness.ts`. Moved it there (mechanical relocation, no logic
change) so the merge module imports both formatters from one place, the way
`applyPreviewMerge.ts` does. **No `statusLabels.ts` addition was needed this
time** -- this vocabulary has no gaps and isn't the group-mode overflow case
PR9-1 hit.

## Result

`GradePreviewPage.tsx` now renders one plan table, one summary sentence,
and one diagnostics region regardless of whether dispatch has run;
dispatching updates the same table and sentence in place rather than
appending a second copy below. Both apply preview and grade preview now
follow the identical pattern from one shared design (PR9-1's decisions),
diverging only where the domains genuinely differ (no group mode here; a
different, but already-handled, result-status vocabulary).

**What should look different in a running app:** where the page used to
show "Repository dispatch preview" (4 counter boxes) immediately above
"Repository rows" (a table), it now shows "Repository dispatch plan" with
one sentence like "1 repository will be dispatched, 1 skipped, 1 blocked."
above the same table. Clicking "Dispatch grading" no longer appends a
second "Grade Dispatch Result Summary" panel, a second repository table,
and a second "Diagnostics / blockers" panel below the first three -- the
existing sentence and table update in place (a row that read "Would
dispatch" now reads "Dispatched" or "Failed"), and there is exactly one
diagnostics panel, present only when there's something to show. "Dispatched
at" now shows a formatted date instead of a raw ISO string.

Screenshot requirement remains unmeetable per backlog item 16 -- not
claimed.
